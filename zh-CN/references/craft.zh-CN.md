# 镜头、剪辑与屏幕文字

## 0. 随长度变化的规模

工具包里的每一个计数都跟着片长走；没有任何东西固定在 30 秒的尺寸上。一张表，两种模式共用：

| 时长 | 镜头或节拍数 | 章节（内部） | 需要调研的关键元素 | 开放参考（参考板） | 方向选定后的剧照（Film mode） |
|---|---|---|---|---|---|
| 15–30 s | 4–8 | 无 | 2–3 | 5–8，一块板 | 3（选定的那一行） |
| ~60 s | 5–15 | 2–3 | 3–5 | 8–12，一块板 | 3 + 每章 2 |
| 1–3 min | 5–45 | 4–8 个 15–30 s 的章节 | 每章 2 | 每章 3–4（12–30），每章一块板 | 3 + 每章 2–3 |
| 3–8 min（Film mode） | 15–120 | 8–20，分成 3–5 幕 | 每章 2 | 每章 3–4（30–70），每幕一块板 | 每章 2–3，按幕测量 |

- **镜头数 = 时长 ÷ 平均镜头长度**，平均长度由片子的节奏决定：动感型约 4 s（8 min ≈ 120 个镜头），标准型约 6 s（≈ 80），沉思型 8–12 s（≈ 40–60）。表里的区间从 12 s 一直到 4 s；把选定的平均值写进 roadmap。长的片子会呼吸：它的平均值可以比 30 秒的片子更长，故事跑起来的地方就快一些。
- **方向板无论多长都保持三行**：它为整部片子选定一种视觉语言，所以永不增长；增长的是选定之后的取材量（按章、按幕）。
- **每个决策的耗量恒定：** 板按章或按幕制作，每块最多 12 张缩略图；只读一行行的摘要，用户看到的是正在讨论的那一章的板。长片花掉的是更多参考，不是更大的上下文。
- 超过 3 分钟就是 Film mode（Quick mode 上限约 3 分钟，`quick-mode.md` §7）。

## 1. 镜头

- **按长度定镜头数**（§0；15–30 s 为 4–8）。每个镜头只有一件要做的事（一次读解）和一个动作：它的主体做了某件事，写在镜头的 `action` 里。仅有摄影机运动不构成一场戏；摄影机是跟着动作走的。`qc.py action <video> <boundaries>` 会标出那些在去掉运镜后画面几乎不变的镜头。
- **一次只给一个重要读解。** 给每个读解留时间：简单形状 ≥ 0.5 s，新东西 1.5–3 s。
- **每次切换都要一个全新的取景：** 改变景别（远/中/近）、角度或镜头焦段。只有故意重复某个取景时才这么做（母题，`"motif": true`）。
- **镜头焦段：** 18–24 mm 用于空间与尺度，35–50 mm 用于自然场景，85 mm 以上用于隔离与压缩。每部片子保持一小套（2–3 个）。
- **每个镜头的运镜行：** 名称、秒数、速度缓动、目标（"dolly in, 3 s, slow ease-in-out, toward the figure"）；名称、感觉与默认值见 `camera-moves.md`。
- **运镜在镜头的第 0 帧就已经在动**，到切点时仍在动，除非静止本身就是重点。真实的 3D 运镜（dolly、crane、orbit）带来视差；变焦会把空间压平。
- **光引导注意力：** 最亮、最锐、饱和度最高的区域就是眼睛会去的方向；把读解放在那里。

## 2. 开场钩子（硬规则）

头 2 秒从第 1 帧起就在动，并以动作为先导：主体在第 1 帧就在做事，摄影机跟着它走。就从运动本身开场；标题、logo 和淡入都排在它之后（或干脆不要）。声音与画面同时开始。

自查：`python3 tools/qc.py hook <video>`（0–2 s 的运动能量；默认阈值 0.5，若用户明确选了一个刻意安静的长片式开场则用 0.1），并查看条带 `python3 tools/qc.py strip <video> 0 2 12`，免得把颗粒误当成运动。在渲染出的画面上跑（粗剪片段或成片都行）；只由静帧卡片组成的 animatic 按设计就会不合格。

## 3. 节奏

| 形式 | 典型镜头长度 |
|---|---|
| 9:16 社交短视频，15–30 s | 4–8 个镜头（§0）；每 2–3 s 有新东西 |
| 16:9 电影感，60–120 s | 3–8 s；画面仍在揭示时可以做更长的停留 |

- **在动作处切**（一个动作在前一个镜头起、在下一个镜头收）或在声音处切。
- **结尾保留属于它自己的秒数**，在最后一句之后（`writing.md` §15）。
- **先锁定旁白和音乐的时间，再剪画面。**

**长片可以展示自己的章节**（5 分钟及以上：YouTube 纪录片、解说、视频随笔），前提是这种形式用得上（很多强纪录片是不带卡片的流动；由该品类的参考来决定，`writing.md` §13）。这样弧线依然只有一条，观众得到路标：在每一幕或每一章的边界放一张 2–3 s 的**章节卡**（一个编号和一个用片子显示字体排的短标题、自有的色调色偏、进出动效、配乐里的一记音效或一个重音），绝不做无声的黑场静帧。卡片以新的形式重述那个悬而未决的问题，或点明这一章要回答什么，于是再次勾住观众。在视频描述里用时间戳列出同样的章节（YouTube chapters）。短片（约 3 分钟以内）保持章节隐形。

**节拍类型。** 节拍表（Quick）或 roadmap（Film）里的每个节拍都得有一种类型；类型决定它的节奏、剪辑和声级。顺序因片而异；类型及其节奏会反复出现。据 cth9191/animate（MIT），在其作品上实测得出。

| 类型 | 它做什么 | 节奏 | 每秒剪辑数 | 声音 | 长度 |
|---|---|---|---|---|---|
| start | 主体静止，世界在前 | hold | 0 | 安静 | 1–1.5 s |
| build | 一个取景，细节聚拢 | hold，小幅运动 | 0–1 | 渐起 | 3–6 s |
| change | 主体的形态或状态改变 | 踩在八分音符上 | 1–5 | 改变处一记重音 | 2–3 s |
| travel | 在路上 | 一段连续运镜 | 依该运镜的分步 | 渐起的衬底或 groove | 2–4 s |
| journey | 许多地方，世界 | 分步，随后在网格上加速的蒙太奇 | 3–8 | 平稳的 groove | 5–9 s |
| turn | 可能出错，或一切聚拢 | 缓慢累积，然后在 1–3 帧内改变 | 0 → 2 | 一次坠落，随后是最响的一击 | 1–3 s |
| quiet | 独自，静止 | hold | 0 | 最低 | 1–1.5 s |
| connection | 主体遇见了它为之而存在的东西 | 停留，缓慢运动 | 0–1 | 温暖，膨胀 | 3–7 s |
| time passes | 后来 | 在二分音符上的闪烁，或光线在一个取景里变化 | 分步 | 无起音 | 约 1 s |
| ending | 标题，最后一个画面，回到起点 | 停留 | 0 | 渐隐或保持 | 2–4 s |

- **最响的一击标记的是转折（turn），不是连接（connection）。**
- **"快"多半是同一个运镜的分步，而不是很多镜头：** 一段"快切"往往就是一个运镜踩在二分音符上。
- **每一次剪辑都有一个你能大声说出来的理由：** 过程的下一步 · 主体守住位置而世界在变 · 这个变成那个（形态变形） · 进入主体内部或从中出来（光圈） · 进入它内部或它周围的一切（同一主体放大或缩小 5–20 倍） · 主体所看到的 · 这个导致了那个 · 之后（时间跳切） · 回到之前那个画面，但已改变（回扣）。没有理由的剪辑就是该删掉的那一次。
- **实测：** `validate_shots.py` 会在镜头长度过于平均（离散度低于 0.30）、连续五个以上镜头长度大致相同时，或每一幕/每一章都保持同一种节奏时发出警告。

## 4. 屏幕文字

- 每张卡片 ≤ 6 个词；在屏时长 ≥ 0.6 s + 每词 0.25 s；短广告或情绪片 1–3 张卡片；一部做信息的片子（纪录片、解说、无旁白的片子）则让文字和图形在它们能说话的地方出现（`motion-design.md`）。
- 按片子的 TYPE 角色设定（`typography.md`：配对、字号、手机端下限、字距、土耳其语大写规则）；放在构图为它留出空间的位置。
- 在引擎里绘制（`engine/scene.html` 里的 `OVERLAY`，`looks.mjs` 里的 `drawOverlay`），这样它就属于那帧确定性的画面。
- **9:16 安全区**（1080×1920）：文字和关键动作不要进入顶部 12 %（230 px）、底部 20 %（384 px）和右侧 10 %（108 px）；平台按钮和字幕都在那些区域。1:1 和 4:5 留 6 % 边距，16:9 留 5 %（`purpose-ad.md`）。
- **屏幕上的身份标识。** 在地点、产品、品牌或宣传片里，当身份很重要时要在屏幕上点出关键元素（地标、产品、制造者、街道）：用片子的字体的短标签或下三分之一字幕，停留足够读完。它们补全具体性测试（`writing.md` §12）：画面呈现只有这个主体才有的东西，标签确保观众知道这是谁的。
- **给每个字母留出头顶空间。** 文本框或底板依据字体的 ascent 与 descent 以及字符串自身的墨迹再加内边距来定尺寸，绝不能只按字号定；新字体和每一个框都要用 `İĞÜŞÖÇ ÉÅ Ñ` 测试，让点、 breve、下加符和环形都留在框内（Quick mode starter 里的 `label()` 就是这么做的）。

## 5. 字幕（仅在用户要求时）

- 最多**两种语言**，上下堆叠：主语言在上，第二种更小、斜体、略暗，放在下面。
- 放在安全区内：9:16 时在底部 UI 区之上；16:9 时在下部横带里。
- 每行 ≤ 42 个字符，主语言每秒 ≤ 17 个字符。
- 从旁白本身计时，绝不从脚本估算来算：每条 `VO` 行配一条字幕，用它实测的 `at` 和 `dur`（`film.html` 的 `VO` 表或 `shots.json`），行过长时在停顿处拆分。不需要额外工具；只有词级计时（下面的动态字幕）才需要 Whisper，且只在用户同意后安装。
- 在引擎里绘制（`OVERLAY` 中的 `{ t: [a, b], sub: ['primary', 'second'] }`），并为每种语言另写一个 `.srt` 供上传。
- 不要给设计音配字幕（倒放的耳语、远处的回声）。

## 6. 动态分镜

由同一份 `shots.json` 生成的低分辨率定时视频，与成片同源：灰卡、静帧或粗渲染，每个镜头配真实的屏幕文字和旁白行、临时声音、真实的切点。

```bash
python3 tools/animatic.py shots.json --out renders/animatic-v1.mp4 [--stills review/stills] [--clips renders/rough] [--vo audio/temp_vo.wav]
```

问用户一个问题："节奏对吗？有没有哪个镜头太长或太短？"

## 7. 平台

| 平台 | 规格 | 注意事项 |
|---|---|---|
| Reels / Shorts / TikTok | 1080×1920，9:16，24–30 fps | 2 s 内有钩子，静音也能看懂，安全区 |
| YouTube | 1920×1080 或 3840×2160，16:9 | 可以有更长的停留；要有一帧能当封面的海报帧 |
| Feed 帖子 | 1080×1080（1:1）或 1080×1350（4:5） | 以中心为重心的构图 |

**X、Slack 和 Discord 上的封面。** 它们把第一帧当作缩略图，并忽略上传的封面；第 0 帧是动的（钩子规则），所以它可能是一团糊。Quick mode：当 `STATE.md` 的 **Delivered to:** 点名 X、Slack 或 Discord 时，`make.py final` 会写出它。Film mode：另写一个文件，其第 0 帧是海报帧（`make.py` 挑中的那一帧），主文件保持原样：

```
ffmpeg -i "<Title>.mp4" -i review/qc-film-vN/thumb-<…>-768.jpg -filter_complex "[1:v][0:v]scale2ref[p][v];[v][p]overlay=0:0:enable='eq(n,0)'" -c:a copy -pix_fmt yuv420p "<Title>-x.mp4"
```

## 8. 屏幕上的软件：UI 主视觉镜头

当主体是一个应用、一个网站或一件工具时，要像摄影机拍产品那样拍界面，而不是拍一段平面的录屏。

- **故事优先：** 屏幕上依次发生的那 4–7 件事、产品明显做出惊人之处的那一个回报点、可信的演示内容（看起来真实的名字、数字和文字；稀疏的灰色占位符会读作模型稿），以及最后一行文案。
- **UI 是暗场里被照亮的物体。** 把真实界面（高分辨率截图，按镜头需要的放大倍率渲染，让文字保持锐利）放在一个平面上，后仰 30–50°，在平面内旋转 10–20° 让文字行呈斜向，再加一点偏航。近处的文字约为远处文字的 1.5 倍。每次切换都把斜向翻过来。画面至少四分之一保持接近全黑。
- **尺度节奏：** 大特写（一个按钮、一个标签页）和特写（一行输入、几行内容）撑起整部片子；中景承载较长的过程；把唯一一个近乎正面的全景镜头留给回报点，然后再回到特写。
- **镜头长度跟随动作：** 过程镜头（打字、答案流出、文档自行写成）5–9 s，重音（切换标签、按下）2–3.5 s，交替进行。动作在切点后 0.3–0.8 s 内开始，结果停留 0.5–1 s，切点在摄影机仍在漂移时到来。
- **焦点负责指示。** 景深跟随倾斜平面上的深度，所以只有一至四行深的一条带是清晰的（Quick mode 里的 `plane()` 配合 `rackFocus`；Film mode 里的景深效果）。注意力移动时移焦（0.4–0.8 s）。
- **光跟随主体，晚了半拍。** 一片柔和的中性光池落在 UI 平面上，沿着动作方向拉长，热区偏向一侧；它比主体晚约 0.3–0.5 s 到达（取主体近期位置的平均值，从而保持为时间的纯函数），并在回报点处开得更宽。不要扫过的反光，不要彩色灯光：唯一的颜色来自产品自身。
- **UI 自己在动。** 不要指针在目标之间旅行：标签页的高亮自己滑过去，按钮显示自己的按下状态，文字以每秒 12–13 个字符的速度输入，生成的文字大约以 0.1 s 的间隔逐行解析出来。UI 镜头之间用硬切；不用叠化。
- **安静的结尾：** 一行文案在黑场上从虚化中浮出，然后静止的 logo 保持 2.5–4 s（尾卡，`purpose-ad.md`）。不要动态 logo，不要在回报点上晃动或闪光；全景镜头才是冲击所在。
- **声音：** 在近乎寂静之上，为每一个可见动作配上贴近的、触感明确的拟音（按键的哒哒声、轻点、发送的呼啸、流动文字下微弱的一层质感），或者把片子的音乐放得很低。
- **像摄影指导那样检查：** 每个镜头的中间取一张静帧，在每个动作的峰值取一张：主体锐利，眼睛半秒就能找到；近处和远处都虚；半尺寸下文字仍可读；相邻镜头在尺度或斜向上有差别。
