# 参考视频："就照这样拍，但改掉……"

用户给出一个他喜欢的视频，并说明要改什么。工具包测量这段视频的**形式**（时长、节奏、观感、声音），用户改掉他们想改的部分，然后影片在这个形式上重新搭建。两种模式都适用。

## 1. 拿到文件

- 让用户把文件放到 `refs/`（他们自己的导出件、他们已经下载好的文件，或一段屏幕录制）。工具包不会下载链接：没有浏览器自动化，未经用户同意也不装新工具。
- 参考只被研究，绝不被复用：它的画面、音乐、镜头、人物、logo 和文字都不会进入影片。带版权的参考在这里没问题；如果用户担心，说明一次即可。

## 2. 测量

```bash
python3 tools/ref_video.py analyze refs/<video> --out research/ref-video
```

它会打印四行（格式 · 节奏，含镜头数、平均镜头长度和速度词 · 观感词与配色 · 声音：BPM、响度，以及有多少个剪切点落在节拍上），并写出 `research/ref-video/REFERENCE.md`、`reference.json`（带观感补丁，做法同 `direction.py measure`）、`sheet.jpg`（每个镜头一帧，按顺序排列），以及方向板格式下的那些帧。看一次 contact sheet，填写 "Read from the sheet" 这五行：镜头个性、转场、屏幕文字类型、钩子、结尾。用柔和叠化的视频可能需要 `--threshold 0.2`。

## 3. 问要改什么（一轮）

在一条消息里同时给出 contact sheet 和测出的形式，然后只问一个问题："Neyi değiştirelim? / What should change?"（改点什么？）并列出最可能的三个选项（★ none 表示无推荐项）、支持多选，再给一个 "Other" 让用户用自己的话填写，例如：想法与主题（永远是新的）· 观感（色彩、光线、风格）· 速度 · 声音或音乐 · 时长或画幅。把用户的话写进 `REFERENCE.md` 的 "Changes the user asked for" 区块；每一条都覆盖对应的那一行。

想法绝不取自参考：如果用户没给，就问他（或者针对新主题给出 2-3 种对参考形式的解读）。

## 4. 在这个形式上搭建

- **Quick 模式：**跳过参考已经回答了的问题（时长与画幅、风格、声音），除非用户要改。导演卡把保留的每一行都标成 "ref: …"（速度取自其平均镜头长度，配色和光线取自其观感补丁，加上 BPM、转场类型），每一项仍可用日常语言修改。节拍表跟随它的节奏：相同时长对应同样数量的节拍、同样的钩子类型和结尾类型，内容是新的。
- **Film 模式：**参考是方向板上的一行（`direction.py board --row "R|<label>|<nearest style>|research/ref-video" --row "A|…" --row "B|…"`），与另外两个备选并排；选 R 就会在风格帧上采用它实测的观感补丁（`looks.md` §10），它的节奏则决定路线图的平均镜头长度。
- **音乐：**带歌曲的参考保留它的 BPM 和剪切节奏，但不保留那首歌：音乐要么是工具包在该速度下写的配乐，要么是用户自己的曲子（`music-video.md`），要么是 CC 授权曲目（`asset_search.py search --type music`）。
- **不变 ≠ 照抄：**可以是同样的节奏和配色，但绝不会是同样的镜头。模板检查照常适用：某一帧会不会被误认成参考本身的画面？如果会，就重做。

一个保存下来的格式（`formats.py`）和一个参考是同一个概念的两面：格式是你自己影片的形式，参考是别人的形式。
